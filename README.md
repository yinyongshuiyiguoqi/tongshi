# 通事 TONGSHI · 涉外执法现场助手

传智杯参赛作品原型。面向基层民警处理涉外警情的现场辅助工具：一句外语进来，
转写、译意、核身份、找依据、给处置建议和能照着念的双语话术。

## 运行

双击 `start.bat`，或者：

```bash
npm install
npm run dev      # http://localhost:5180
npm run build    # 产物在 dist/
```

## 现在能做什么

- 三个预设场景切换（街头盘查 / 住宿登记 / 涉外纠纷）
- 模拟语音录制、证件上传、文本输入
- 五步处理链路可视化：转写 → 语种 → 核验 → 检索 → 建议
- 处置结论流式输出、动作要点、可照念的中英双语话术
- 依据卡片（法名 + 条号 + 要点）、一键复制话术、导出处置记录

## 接真模型

默认走 Mock，不连网也能完整演示。拿到 API key 后：

```bash
cp .env.example .env.local
# 填入 VITE_LLM_BASE / VITE_LLM_KEY / VITE_LLM_MODEL
npm run dev
```

接口按 OpenAI 兼容格式写，DeepSeek、智谱、通义、Moonshot 都能直接用。
顶部状态会从「演示模式」变成「已接入模型」，处置结论改为真模型流式生成。

**安全**：前端直连会把 key 打进 bundle。仓库只提交 `.env.example`，
`.env.local` 已经写进 `.gitignore`；正式上线要加一层服务端代理
（Next.js API Route 或 Vercel Edge Function），否则评审一查仓库就露馅。

## 目录

```
src/
  App.tsx                主界面与流程状态机
  data/scenarios.ts      预设场景、依据条目（★ 需要核对原文）
  lib/ai.ts              大模型接入层（流式）+ 提示词
  styles.css             全部样式
```

## 必须处理的两件事

1. **法条要核**。`data/scenarios.ts` 里的 `summary` 是要点摘录，不是条文原文，
   条号也要对着现行文本逐条核。评审如果抽查依据，这里出错是硬伤。
   建议把 `PROVISIONS` 换成一份经过校验的 JSON，最好带条文原文和生效日期。
2. **AI 能力要补真**。现在只有处置结论接了模型，转写、语种识别、检索还是前端写死的。
   评分里 AI 技术深度占 35%，建议按下面的顺序补。

## 对照评分表还缺什么

| 评分项 | 现在 | 建议补 |
| --- | --- | --- |
| 大模型集成 8% | 有流式调用与提示词约束 | 加输出校验、失败重试、敏感词兜底 |
| Agent / 工作流 8% | 五步是前端模拟 | 改成真正的工具调用：转写工具、检索工具、核验工具 |
| RAG 6% | 关键词硬匹配 | 换成向量检索，法规切块入库，展示召回与重排 |
| 多模态 5% | 只有文字 | 接语音识别（Whisper 或浏览器 Web Speech）+ 证件 OCR |
| AI 安全 4% | 页底有免责 | 加输出拦截、依据缺失时拒答、操作留痕 |
| MCP / 工具 4% | 无 | 把法规查询包成 MCP server，前端通过协议调用 |

按三周算，顺序建议：先把 RAG 和 Agent 做实（14 分），再做语音和 OCR（5 分），
MCP 放最后做加分项。

## 已知限制

- 录音、上传、检索都是模拟，不产生真实数据
- 处置记录导出为 txt，正式版应生成可归档的表格或 PDF
- 场景只有三个，演示够用，答辩时评委可能追问其他情形
